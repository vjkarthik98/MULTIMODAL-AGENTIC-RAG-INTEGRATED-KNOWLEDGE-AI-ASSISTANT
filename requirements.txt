# LLM — llama-cpp-python
# ── This line installs the prebuilt CPU (BLAS) wheel — correct as-is for a
#    CPU-only box; device_manager.llm_gpu_layers() returns 0 automatically
#    when torch.cuda.is_available() is False, so gguf_model.py runs Mistral-7B
#    Q4_K_M on CPU with no code changes needed.
# ── On a CUDA box (AWS g6e.xlarge / L40S), the prebuilt wheel's dynamic
#    backend registers 0 GPU devices → silent CPU fallback at ~5 tok/s.
#    Rebuild from source against the system CUDA toolkit — see
#    install_cuda.sh, or:
#   CMAKE_ARGS="-DGGML_CUDA=on -DGGML_BACKEND_DL=OFF -DGGML_NATIVE=OFF \
#     -DCMAKE_CUDA_ARCHITECTURES=89 -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc" \
#   CUDACXX=/usr/local/cuda-12.8/bin/nvcc CUDA_HOME=/usr/local/cuda-12.8 \
#   pip install "llama-cpp-python==0.3.30" --no-binary llama-cpp-python --force-reinstall --no-cache-dir
#
# llama.cpp runs as a SEPARATE process (llama-server, own CUDA context on GPU
# boxes) — in-process it corrupts PyTorch's CUDA context on worker threads and
# SIGSEGVs the embed stage. start_server.sh launches `python -m llama_cpp.server`;
# the sse-starlette + starlette-context deps below are required by that server.
