================================================================================
SCORING MATRIX FOR BROKEN CORPUS TESTS
================================================================================

For each query, record:

| Column              | Values                                      |
|---------------------|---------------------------------------------|
| Chunk Retrieved?    | Yes / No / Wrong chunk                      |
| Noise Handled?      | Clean extraction / Partial / Noise included |
| Answer Correct?     | Correct / Partially correct / Wrong         |
| Hallucination?      | None / Minor (memory bleed) / Major         |
| Contradiction Flagged? | Yes / No / N/A                           |

Key Metrics to Report:
- Noise Retrieval Rate: % of noisy chunks correctly surfaced in top-k
- Hallucination-on-Empty Rate: % of blank-doc queries where model hallucinated
- Contradiction Detection Rate: % of conflicting queries where model flagged conflict
- Error Propagation Rate: % of queries where corpus errors (e.g., ada-003) were
  repeated as facts in the answer
- Version Accuracy: % of versioned queries where the authoritative version was used

================================================================================
RECOMMENDED TEST PROTOCOL FOR BROKEN CORPUS
================================================================================

Phase 1 — Baseline:        Run rag_benchmark_queries.txt on rag_test_corpus.txt
Phase 2 — Stress Test:     Run THIS file on rag_broken_corpus.txt
Phase 3 — Delta Analysis:  Compare Phase 1 vs Phase 2 scores per metric
Phase 4 — Fix & Retest:    Add preprocessing (dedup, noise strip, OCR correction)
                            and rerun Phase 2 to measure improvement

The delta between Phase 1 and Phase 2 is your pipeline's "dirt sensitivity score."
A robust pipeline should degrade less than 15% across all metrics.
